# ARTIST · Team Space (MVP)

Тёмное мобильное веб-приложение для кальянной «Артист»: зарплата по категориям, график, заявки на обмен сменами с подтверждением старшего мастера, ручная инвентаризация, роли и общая онлайн-база.

## Уже есть
- Авторизация по email и паролю через Supabase Auth.
- Профили и роли `master`, `senior`, `admin`.
- Начисление по категории продажи: фиксированная сумма или процент от суммы чека.
- Настраиваемые ставки (только для старшего мастера/администратора).
- Общий график смен.
- Заявки на обмен сменой и подтверждение/отклонение менеджером.
- Номенклатура инвенты, ручной фактический пересчёт и история.
- Row Level Security (RLS) на таблицах.

## Подключение базы
1. Создай проект в [Supabase](https://supabase.com/dashboard).
2. Открой SQL Editor и выполни весь файл `supabase/schema.sql`.
3. В Settings → API скопируй Project URL и `anon`/publishable key.
4. Скопируй `.env.example` в `.env` и заполни значения:
   ```
   VITE_SUPABASE_URL=https://....supabase.co
   VITE_SUPABASE_ANON_KEY=...
   ```
5. Установи Node.js LTS на компьютер и выполни в папке проекта:
   ```
   npm install
   npm run dev
   ```
6. Создай свой аккаунт через приложение.
7. В SQL Editor назначь себе роль администратора, подставив свой email:
   ```
   update public.profiles
   set role='admin'
   where id=(select id from auth.users where email='YOUR_EMAIL');
   ```
8. Обнови приложение и создай аккаунты мастеров. У каждого мастера будет отдельный вход. Для production рекомендуется приглашать сотрудников администратором, а не публиковать открытый доступ к регистрации.

## Публикация в интернете
Проект можно развернуть на Vercel или Netlify как Vite-приложение. Добавь `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в переменные окружения сервиса и опубликуй проект. После публикации ссылка будет открываться на iPhone; в Safari можно выбрать «Поделиться → На экран Домой».

## Важно перед реальным использованием
- Значения ставок в `schema.sql` — стартовые примеры, их нужно сверить с фактическими правилами «Артиста».
- В текущем MVP продажи записываются мастером и рассчитываются по действующим ставкам при просмотре; для официального расчёта зарплаты лучше добавить закрытие периода и фиксацию ставок на момент продажи.
- В MVP одобрение заявки меняет её статус; автоматическое переназначение смены на другого сотрудника нужно сделать следующим этапом после определения правил обмена.
- Инвентаризация фиксирует фактический остаток и расхождение с введённым учётным остатком; автоматическое списание товаров не включено по требованиям ручного пересчёта.
- Перед использованием на реальных данных протестируй RLS и роли на отдельных тестовых аккаунтах.
- Никогда не добавляй `service_role` key во фронтенд. Только anon/publishable key при включённом RLS.
